# TotemAlchemy

TotemAlchemy 是 Totem 系列的生存煉金模組，包含豬糞、缽、木灰、硝石、
火藥、熱可可、櫻花釀與資料驅動煉藥鍋。

## 遊戲內 Totem 手冊

手持普通書對釀造台按右鍵，即可取得或刷新共用的 `Totem 手冊`。Alchemy
章節使用物品與藥水圖示列出每種釀造材料的成功率、所有可能效果、基底替代
懲罰、紅石／螢石／火藥／龍息加工，以及櫻花迅捷、螢草力量和三種煉藥鍋
配方。滑鼠停留在圖示上可查看原版完整提示；安裝 Nexus 或 Remnant 時，
Alchemy 章節會自動整合到同一本手冊。

材料效果頁是玩家個人的動態研究紀錄。成功釀造後，實際得到的「材料 → 藥水效果」
才會從未知圖示解鎖；失敗與尚未抽中的其他效果不會提前揭露。紀錄儲存在世界中，
換書與重新登入仍會保留。多人靠近同一座釀造台時，由完成當下最近的非旁觀玩家取得紀錄。
效果索引會反向整理同一筆研究：解鎖效果名稱，並列出玩家已確認能釀出該效果的材料。
Alchemy 使用共用 Totem 手冊的第一章排序；手冊封面與目錄之後會優先顯示煉金內容。

目前版本為 **0.1.23**，精確搭配 TotemCore **0.6.0**。

## 安裝

Client 與 Server 都放入：

1. Fabric API `0.154.2+26.2`
2. TotemCore `0.6.0`
3. TotemAlchemy `0.1.23`

| 項目 | 需求 |
| --- | --- |
| Minecraft | 26.2 |
| Fabric Loader | 0.19.3+ |
| Java | 25+ |
| 必要 Totem 模組 | `totem-core =0.6.0` |

Alchemy 不依賴其他功能模組。使用 DeadRecall 2.4.11 整合 JAR 時不要再
安裝獨立 TotemAlchemy。

獨立安裝只註冊 `totem:alchemy/*` canonical 物品；舊
`deadrecall:*` 物品 ID 的解碼與轉換只由 DeadRecall 相容整合包提供。

## 入門材料

### 缽

工作台：

```text
S F S
_ S _
```

`S` 可使用石頭、鵝卵石、安山岩、閃長岩、花崗岩、黑石或深板岩碎石；
`F` 是燧石。

缽的常用配方：

- 缽 + 可可豆 + 糖 → 裝可可粉的缽。
- 缽 + 礫石 → 燧石，缽會返還。
- 缽右鍵硫磺方塊 → 帶硫磺的缽；方塊會被消耗。

### 豬糞

對可正常餵食的豬餵食成功後，牠會在約兩秒後於腳下留下豬糞。同一格
可像雪一樣堆到八層；使用鏟子收集，每層得到一份。

豬糞可以投擲，被命中的生物會得到「臭味」效果並使附近友善生物遠離。

### 木灰與火藥

- 熔煉乾草捆可取得木灰。
- 帶硫磺的缽 + 硝石 + 煤炭或木炭，可無序合成 4 個火藥。

## 煉藥鍋教學

煉金流程使用原版煉藥鍋，並在下方放置點燃的營火。依配方右鍵投入
材料；標記為 dropped-only 的材料要丟進鍋內。烹煮完成會播放提示音。

每次投入材料都會立即獨立判定，基準成功率約為 **80%**，並依材料難度
動態變化。成功的材料才會記入鍋內配方；失敗時該份材料會消耗並冒出黑
煙，但先前已成功加入的材料與液體會保留，玩家只需重試失敗的材料。內
建材料目前介於 75%～90%，因此成功率不再是整鍋固定值。

原版釀造台也套用相同的動態成功率，並直接使用世界目前註冊的原版
釀造規則，所以粗製藥水、所有效果藥水、延長、強化、噴濺與滯留轉換都
包含在內。每次釀造材料將被消耗時都判定一次；成功時三個瓶槽依原版配方
轉換，失敗時藥水保持原狀，可補充材料重試。漏斗與其他使用原版釀造註冊
表的配方也會自動遵守此規則。

原版材料機率如下：

| 材料 | 成功率 | 材料 | 成功率 |
| --- | ---: | --- | ---: |
| 紅石 | 92% | 糖 | 90% |
| 地獄疙瘩 | 88% | 石頭 | 87% |
| 金胡蘿蔔 | 86% | 蜘蛛眼 | 85% |
| 岩漿球 | 84% | 鑲金西瓜片 | 83% |
| 烈焰粉 | 82% | 史萊姆方塊 | 81% |
| 河豚 | 80% | 兔子腳 | 79% |
| 幽靈之淚 | 78% | 發酵蜘蛛眼 | 77% |
| 夜魅皮膜 | 76% | 螢石粉 | 75% |
| 火藥 | 74% | 蜘蛛網 | 73% |
| 旋風棒 | 72% | 海龜殼 | 71% |
| 龍之吐息 | 68% | 未知模組材料 | 80% |

紅色蘑菇可以代替地獄疙瘩，將水瓶釀造成粗製藥水，單次成功率為 **65%**。
失敗時紅色蘑菇會消耗但水瓶不變，可以補充蘑菇重試；地獄疙瘩仍有 88%
成功率，因此進入地獄取得原材料依然是更可靠的選擇。紅色蘑菇製成的粗
製藥水會成為「不穩定基底」，之後每一步釀造的材料成功率都會再降低
**20 個百分點**，而且標記會跟著普通、延長、強化、噴濺與滯留結果持續
傳遞。例如糖原本為 90%，使用不穩定基底時降為 70%；紅石從 92% 降為
72%。同一批混放穩定與不穩定藥水時，整批採用較低機率。

### 多結果效果池

材料融合成功後，主效果材料會從自己的效果池隨機抽出一種結果。同一批
三瓶共享同一次抽選，不會產生三種不同結果。二結果池各為 50%，三結果
池各約為 33.3%：

| 投入粗製藥水的材料 | 可能結果 |
| --- | --- |
| 蜘蛛眼 | 劇毒／虛弱 |
| 紅色蘑菇 | 劇毒／飽食 |
| 鑲金西瓜片 | 治療／抗性 |
| 糖 | 迅捷／緩慢／飽食 |
| 兔子腳 | 跳躍提升／緩降／迅捷 |
| 岩漿球 | 抗火／抗性／力量 |
| 金胡蘿蔔 | 夜視／隱形／治療 |
| 烈焰粉 | 力量／抗火／傷害 |
| 幽靈之淚 | 回復／治療／虛弱 |
| 河豚 | 水下呼吸／劇毒／虛弱 |
| 海龜殼 | 龜仙／水下呼吸／抗性 |
| 夜魅皮膜 | 緩降／隱形／夜視 |
| 旋風棒 | 蓄風／緩降／跳躍提升 |
| 史萊姆方塊 | 滲漿／跳躍提升／緩慢 |
| 石頭 | 寄生／抗性／緩慢 |
| 蜘蛛網 | 織網／緩慢／虛弱 |
| 發酵蜘蛛眼 | 虛弱／傷害／隱形 |

效果抽選只會在材料融合成功後發生。例如蜘蛛眼先通過 85% 的融合判定，
才會以各 50% 抽出劇毒或虛弱。紅色蘑菇放入水瓶時仍是地獄疙瘩替代配
方；放入粗製藥水時才使用劇毒／飽食效果池。

飽食藥水可用螢石粉強化；抗性藥水可用紅石延長至 8 分鐘，或用螢石粉
強化為 90 秒的抗性 II。這些後續結果也會保留不穩定基底標記。

地獄疙瘩維持基底製作；紅石、螢石粉、火藥與龍之吐息維持延長、強化、
飛濺及滯留用途，不進入效果池，讓玩家仍能控制藥水的後續加工方式。

### 硝石

1. 將煉藥鍋裝滿三層水，下方放點燃營火。
2. 投入木灰、紅色或棕色蘑菇、豬糞。
3. 每份材料各烹煮 200 ticks，並消耗一層水。
4. 完成後鍋旁會產生一份硝石。

### 熱可可

1. 在空煉藥鍋下放點燃營火。
2. 用牛奶桶右鍵開始，空桶會返還。
3. 加入裝可可粉的缽，取得空缽。
4. 將糖丟入鍋內。
5. 等待 200 ticks，再用玻璃瓶裝取熱可可。

### 櫻花迅捷藥水

1. 使用三層滿水煉藥鍋與點燃營火。
2. 加入糖、櫻花樹葉、發光莓與甜莓。
3. 等待 240 ticks。
4. 用玻璃瓶裝取櫻花迅捷藥水；飲用後會得到 3 分鐘的櫻花迅捷效果。

它是迅捷藥水的變異分支：釀造台可用櫻花樹葉把普通、延長或強效迅捷藥水
轉成對應階級的櫻花迅捷藥水。效果比同階原版迅捷高 10%：基本效果提升
22% 移動速度，強效版提升 44%，
並保留移動與攻擊時的櫻花粒子。基本櫻花迅捷也能用紅石延長或螢石粉強化。

### 螢草力量藥水

在釀造台中用螢火蟲灌木叢轉化普通、延長或強效力量藥水，即可得到對應階級
的螢草力量藥水，該材料每次投入有 82% 成功率。效果比同階原版力量高 10%：
基本效果增加 3.3 點攻擊傷害，強效版增加 6.6 點；效果持續時會環繞螢火蟲，攻擊命中時也會在目標旁迸出
螢火蟲粒子。基本螢草力量也能用紅石延長或螢石粉強化。

## Data Pack 擴充

煉藥鍋配方位於：

```text
data/<namespace>/deadrecall/cauldron_recipes/*.json
```

內建範例在
[`src/main/resources/data/deadrecall/deadrecall/cauldron_recipes/`](src/main/resources/data/deadrecall/deadrecall/cauldron_recipes/)。
格式可定義起始鍋狀態、初始水位、營火需求、逐材料／全投入後烹煮、
ticks、容器返還、完成音效與掉落／裝瓶結果。配方頂層的
`success_chance` 是所有材料的預設值，材料物件內也能個別指定同名欄位
覆寫；範圍為 `0.0`～`1.0`，省略時預設 `0.8`。亦可用
`success_message`、`failure_message` 與 `failure_sound` 自訂回饋。

## 舊世界相容

新取得的八個煉金物品使用 `totem:alchemy/<物品名稱>` canonical ID，例如
`totem:alchemy/stone_bowl` 與 `totem:alchemy/cherry_brew`。模組仍註冊全部
舊版煉藥鍋 NBT（包括舊 `HOT_COCOA` 狀態）仍由 Alchemy 自己讀取。
`deadrecall:*` 物品 ID 則由 DeadRecall 整合包註冊；Core 遷移表讓配方與
煉藥鍋接受舊堆疊並只產生 canonical 結果。升級前請先備份世界；不要同時
安裝整合 JAR 與獨立功能 JAR。
